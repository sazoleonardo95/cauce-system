## 1. QUE ES EL PROYECTO

CauCE es un sistema de ventas e inventario completo con 3 partes:
- **Backend** (API): Node.js + Express + Prisma ORM
- **Frontend** (Web): Next.js 14 + Tailwind CSS
- **Mobile** (App Android): React Native + Expo SDK 51

Permite gestionar productos, bodegas, inventario, ventas, clientes, y un sistema de invitaciones por email con 4 roles: Admin, Gerente, Vendedor, Bodega.

      productController.js     # CRUD productos

      notificationController.js # CRUD notificaciones in-app + register device token

## 5. MODELOS DE LA BASE DE DATOS (Prisma Schema)

Modelos principales:
- **User**: id, email, password, firstName, lastName, phone, role (ADMIN/MANAGER/SELLER/WAREHOUSE), avatar, isActive, companyId, managerId
- **Company**: id, name, slug, ownerId, logo, address, phone, email, website, taxId
- **Product**: id, name, sku, barcode, price, cost, category, description, minStock, isActive, companyId
- **Warehouse**: id, name, code, address, isActive, companyId
- **InventoryItem**: id, productId, warehouseId, quantity (compound unique: productId_warehouseId)
- **Sale**: id, saleNumber, status (COMPLETED/CANCELLED/PENDING), subtotal, taxRate, taxAmount, discount, total, notes, paymentMethod, saleDate, companyId, sellerId, customerId, warehouseId
- **SaleItem**: id, quantity, unitPrice, discount, saleId, productId
- **Customer**: id, name, email, phone, address, taxId, notes, isActive, companyId
- **Invitation**: id, email, role, token, status (PENDING/ACCEPTED/CANCELLED/EXPIRED), expiresAt, companyId, invitedById, acceptedAt
- **Notification**: id, title, message, type, isRead, data, userId
- **StockMovement**: id, type (ENTRY/EXIT/ADJUSTMENT), quantity, reference, notes, productId, warehouseId, createdById
- **Commission**: id, amount, isPaid, sellerId, saleId
- **DeviceToken**: id, token, platform, isActive, userId (PARA NOTIFICACIONES PUSH - pendiente de crear tabla)

## 7. DECISIONES TECNICAS IMPORTANTES

1. **Currency format**: Usar `toLocaleString('es-CO')` - muestra $1.234.567 sin .00 para enteros
2. **Registration flow**: Crear user primero, luego company con ownerId, luego actualizar user con companyId
3. **Dashboard route auth**: `/api/dashboard/stats` NO tiene authorize() middleware - el controller filtra por rol internamente
4. **Sidebar admin**: Los items Bodegas, Equipo, Invitaciones tienen `adminOnly: true` - el Sidebar los oculta para roles no-admin
5. **Sale inventory**: Solo descuenta stock si `warehouseId` esta presente en la venta
6. **Firebase degradation**: Si no hay FIREBASE_PROJECT_ID en env vars, no crashea - solo log warning
7. **Push notifications**: Fire-and-forget (`.catch(() => {})`) - nunca bloquean la request
8. **Invalid tokens**: Si Firebase retorna token invalido, se desactiva en DB automaticamente
9. **Search en mobile**: `useFocusEffect` con `[]` (no `[search]`) - la busqueda es client-side con filter
10. **Double-submit protection**: Todos los forms tienen estado `saving` que bloquea submit repetido

## 8. BUGS CORREGIDOS (NO VOLVER A COMETER)

| Bug | Causa | Fix |
|-----|-------|-----|
| ProductsScreen crash | Archivo corrupto (minificado a 15 lineas) | Reescrito con formato correcto |
| Dashboard lento | `[search]` en useFocusEffect causaba API call por tecla | Cambiado a `[]` |
| Dashboard muestra "Reintentar" en carga | Boton visible desde el inicio | Spinner limpio, error solo si API falla |
| Crash por nombre null | `item.name[0]` sin null check | `item.name?.[0] \|\| 'P'` |
| "Exito" sin acento | Falta tilde en i | Cambiado a `\u00C9xito` |
| Doble-tap guardado | Sin protection | Estado `saving` en todos los forms |
| formatCurrency inconsistente | Mobile usaba format diferente | Unificado a es-CO en ambos |
| "Sin bodega" confuso | Opcion en picker siempre fallaba | Removida del picker |
